moonbit-subtitle

纯 MoonBit 的 SRT / WebVTT 字幕解析与时间轴处理库

下面六组都是命令行工具的真实输出。每组左边是输入文件，右边是运行结果，没有任何修饰。

选用的输入是刻意挑的脏文件：带 BOM、CRLF 换行、序号跳号又乱序、相邻字幕重叠、时间行两侧留空格。这类文件从字幕组、剪辑软件和在线平台导出来时很常见，现有工具碰到它们往往直接报错，或者悄悄丢掉解析不了的条目。

页面上每条输出都可以自己复现：

git clone https://github.com/AYHEY001/moonbit-subtitle
cd moonbit-subtitle
moon run cmd/main -- info examples/messy.srt

一脏文件能读出什么

info 不改动文件，只报告读到了什么。它对下面这些杂质全部容忍，因为它们都不影响内容的含义。

  • 开头是 UTF-8 BOM，三个字节
  • 换行全部是 Windows 的 CRLF（上面用 ↵ 标出）
  • 序号写成 1、5、2、9，既跳号，第三块还比第二块小
  • 序号 5 那一块从 03.950 开始，早于上一块的 04.000，两段重叠
  • 序号 2 那一行的时间戳两侧各留了空格
  • 序号 5 那一行时间戳后面跟着 SRT 的排版坐标 X1:100 X2:500

二规范化：重排与合并

normalize 做三件事：按开始时间重排、合并重叠的条目、把序号重编成一到 n。同一份文件进去，出来变成两条。

原来的前三块按开始时间排成 01.000 → 01.200 → 03.950，每一段都跟上一段重叠，于是并成一条，结束时间取最晚的 07.000。正文按这个新顺序拼起来，所以序号 2 那两行排到了序号 5 那行前面。

合并之后是一条字幕，位置设置只能留一套，取最先出现那条的。最先那条没有设置，所以序号 5 原来带的坐标 X1:100 X2:500 没有保留。

三跨格式转换

convert 只换格式，不排序也不合并。时间轴和顺序保持原样，序号在 WebVTT 里本来就不需要，时间戳的小数点从逗号换成句点。

坐标 X1:100 是 SRT 的写法，WebVTT 里没有对应的键。挪过去是非法的，所以转格式时丢掉。反过来，WebVTT 的 align:start 转到 SRT 也一样丢弃。两组键名之外的第三种写法两边都会原样带着。

四非字幕块与文件头

WebVTT 里除了字幕，还有 NOTE、STYLE、REGION 三类不显示的块，以及紧跟在签名行后面的文件头元数据。播放器不显示它们，丢了却会改变文件的意思，所以要按原文收好、按原位置写回。

examples/noted.vtt 里有一个 STYLE 块和两条 NOTE，info 会报成「非字幕块：NOTE 2、STYLE 1」。这些块连同文件头都能原位置写回：转一圈回来，夹在两条字幕之间的注释仍在那一对之间。

五剥标记

strip 把正文里的排版标记和字符实体转成纯文本，供翻译、语音合成、全文检索使用。排版设置留在时间行上，不影响。

粗体、类名、说话人标记和逐字高亮的时间戳标记都去掉了。看最后那个说话人的第二行：原文写的是 &amp;lt;，解出来是字面的 &lt; 而不是 <。实体里的 &amp; 放在最后一步替换就是为了这个，顺序反了会解两次。

六不是 UTF-8 就报错

能修的修，修不了的明确报错，带着文件名和块号，不静默丢数据，也不把乱码当文本继续处理。

这份文件的正文是 GBK 编码的「中文字幕」。工具读进来的是原始字节，做严格校验，不合法就报错并给出转码命令。同一条规则也用在结构上：块首行不是序号行、WebVTT 的块里找不到时间行，都会按块号指出位置，而不是悄悄并进上一条或丢掉。
