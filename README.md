# moonbit-subtitle

纯 MoonBit 实现的字幕处理库：解析、变换、渲染 SRT 与 WebVTT，附一个命令行工具。

## 这个库解决什么问题

SRT 看着简单，但从字幕组、剪辑软件、在线平台导出的文件里常混着这些东西：

- 文件开头的 UTF-8 BOM
- Windows 的 CRLF 换行
- 序号跳号、乱序、重复
- 相邻字幕时间重叠几十毫秒，部分播放器会闪烁或丢行
- 时间行两侧多余的空格或制表符，或者时间后面跟着排版坐标 `X1:100 X2:500`

现成的字幕工具大多假设输入是干净的，遇到这些要么报错，要么静默丢字幕。
后者更麻烦，往往到成片导出之后才发现少了几行。

这个库不假设输入干净，能识别出来的杂质直接修掉，修不了的带着块号报错。

## 快速开始

需要先装 MoonBit 工具链：https://www.moonbitlang.com/download/

```
git clone https://github.com/AYHEY001/moonbit-subtitle
cd moonbit-subtitle
moon run cmd/main -- info examples/messy.srt
```

`examples/messy.srt` 是一份故意做脏的文件，带 BOM、CRLF、跳号、重叠和时间行多余空格。
上面那条命令的输出：

```
文件：examples/messy.srt
格式：SRT
条数：4
总时长：00:00:11,000
首条：00:00:01,000
末条：00:00:12,000
```

五个子命令：

| 命令 | 做什么 |
|---|---|
| `info` | 打印条数、总时长、首末时间，以及文件头与非字幕块 |
| `shift` | 整体平移时间轴，`-500` 是毫秒，也可以写 `-1.5s`、`2m` |
| `normalize` | 按开始时间排序、序号重排成一到 n、合并重叠 |
| `convert` | SRT 与 WebVTT 互转，目标格式由 `--to` 指定 |
| `strip` | 剥掉正文里的排版标记和字符实体，输出纯文本 |

除 `info` 外都可以加 `-o` 写进文件，不给就打到标准输出。
退出码：`0` 正常，`1` 文件处理失败，`2` 参数写错。

六组输入输出对照收在 [`demo.html`](demo.html) 里，覆盖这份脏文件的解析与规范化、
跨格式转换、非字幕块与文件头的保留、剥标记，以及非 UTF-8 输入的报错。
单文件，没有外部依赖，下载后用浏览器打开。

开发用的几条命令：

```
moon check          # 类型检查
moon build          # 构建
moon test           # 跑测试
```

测试一共 161 项。其中 12 项是 quickcheck 属性测试，覆盖往返一致性与时间轴不变量
（见 [property_wbtest.mbt](property_wbtest.mbt)）；8 项来自
[README.mbt.md](README.mbt.md) 里的用法示例，也被 `moon test` 真的跑一遍；
另有 15 项在 `cmd/main` 里，测参数与路径处理、读文件的编码校验、`info` 的展示逻辑。

## 命令行的用法

`shift`、`normalize`、`convert`、`strip` 按输入格式写回：VTT 进去还是 VTT 出来，
要换格式得显式写 `convert`。

输入文件必须是 UTF-8。别的编码直接报错、退出码 1，不产出任何东西：

```
$ moon run cmd/main -- normalize old.srt
错误：old.srt：不是合法的 UTF-8 文件。GBK 等编码的字幕请先转成 UTF-8（例如 iconv -f GBK -t UTF-8）
```

### normalize

按开始时间排序、合并重叠、序号重排成一到 n。排序是稳定的，开始时间相同的两条保持原来的先后；
合并时正文里不会多出空行，所以输出的文件总能被自己重新读进来。

```
$ moon run cmd/main -- normalize examples/messy.srt
1
00:00:01,000 --> 00:00:07,000
这一行是普通的字幕
序号比上一条小，但时间靠前
而且时间行两边有多余空格
序号跳到了 5，而且和上一条重叠

2
00:00:09,000 --> 00:00:12,000
这一条时间最晚
```

`messy.srt` 原来四条，序号是 1、5、2、9，时间上有两处重叠。这份输出把它们并成了两条。

### shift

平移量写 `-500` 是毫秒，也可以写 `-1.5s`、`2m`。平移后出现负时间的条目贴到 0，
下面第一条就是这么来的。`shift` 不改条数也不改顺序。

```
$ moon run cmd/main -- shift examples/sample.vtt -1.5s
WEBVTT

00:00:00.000 --> 00:00:02.500 align:start position:10%
这一行是 WebVTT

NOTE 这一段是注释，不是字幕

STYLE
::cue { color: yellow }

intro
00:00:03.500 --> 00:00:06.500
带 cue 标识的一条

00:02:01.956 --> 00:02:03.500
小时省略的写法
```

`examples/sample.vtt` 把几处特性凑在一份文件里：排版设置、`NOTE` 和 `STYLE` 块、
cue 标识、省略小时的写法。平移之后都还在。

### convert

只换格式，不排序也不合并，条数和顺序跟输入一致。SRT 的排版坐标在 WebVTT 里是非法语法，
顺手丢掉：

```
$ moon run cmd/main -- convert examples/messy.srt --to vtt
WEBVTT

00:00:01.000 --> 00:00:04.000
这一行是普通的字幕

00:00:03.950 --> 00:00:07.000
序号跳到了 5，而且和上一条重叠

00:00:01.200 --> 00:00:02.000
序号比上一条小，但时间靠前
而且时间行两边有多余空格

00:00:09.000 --> 00:00:12.000
这一条时间最晚
```

要写进文件就加 `-o out.vtt`。

### strip

把正文里的排版标记剥掉，序号、时间轴、cue 标识都留着。这个形态适合喂给翻译、语音合成、全文检索。

`examples/marked.vtt` 里放了四种写法：`<b>` 加粗、`<c.yellow>` 类选择器、`<v 张三>` 说话人、
`<00:00:09.000>` 卡拉OK 时间戳标签，外加一个 `&amp;` 实体。

```
$ moon run cmd/main -- strip examples/marked.vtt
WEBVTT

intro
00:00:01.000 --> 00:00:04.000 align:start
欢迎收看今晚的节目

speaker
00:00:05.000 --> 00:00:08.000
这句由张三说
A & B 中间还有一个字面的 &lt; 实体

karaoke
00:00:09.000 --> 00:00:12.000
逐字高亮
```

注意 `speaker` 那条的第二行。原文写的是 `&amp;lt;`，解出来是字面的 `&lt;` 而不是 `<`。
`&amp;` 放在最后一步替换就是为了这个，顺序反了会解两次。

## 格式细节

### 时间行右侧的排版设置

两种格式都允许在结束时间后面缀一串设置，控制这条字幕落在画面什么位置：

```
1
00:00:01,000 --> 00:00:04,000 X1:100 X2:500

00:00:01.000 --> 00:00:04.000 align:start position:10%
```

这段原文收进 `Cue::settings`，渲染时写回时间行。丢掉它的话，平移一次字幕位置
就会掉回播放器默认值。`examples/messy.srt` 第二条带坐标，平移一秒之后还在：

```
$ moon run cmd/main -- shift examples/messy.srt 1s
1
00:00:02,000 --> 00:00:05,000
这一行是普通的字幕

2
00:00:04,950 --> 00:00:08,000 X1:100 X2:500
序号跳到了 5，而且和上一条重叠

3
00:00:02,200 --> 00:00:03,000
序号比上一条小，但时间靠前
而且时间行两边有多余空格

4
00:00:10,000 --> 00:00:13,000
这一条时间最晚
```

设置只在写回同一种格式时带上。WebVTT 用规范固定的六个键
（`align` / `line` / `position` / `region` / `size` / `vertical`），SRT 用坐标
`X1` / `Y1` / `X2` / `Y2`，两组没有交集。

所以 `X1:100` 挪进 WebVTT 的时间行是非法语法，转过去就丢掉，上面 `convert` 那个例子里
第二条的坐标就是这么没的；反过来也一样。两组键名之外的第三种写法两边都保留。

### 非字幕块

`NOTE` / `STYLE` / `REGION` 这三类块播放器不显示，丢了却会改变文件的意思。
`STYLE` 里依赖 `::cue` 的样式会失效，`REGION` 定义的字幕位置会消失，
`NOTE` 通常记着译者或时间轴信息。它们按原文收进 `Subtitle::extras`，渲染时写回原来的位置。
夹在两条字幕之间的注释，转一圈回来还在那一对之间。

`examples/noted.vtt` 里两处 `NOTE` 和一个 `STYLE` 块，平移一秒后都还在原位：

```
$ moon run cmd/main -- info examples/noted.vtt
文件：examples/noted.vtt
格式：WebVTT
条数：2
总时长：00:00:07,000
首条：00:00:01,000
末条：00:00:08,000
非字幕块：NOTE 2、STYLE 1
```

```
$ moon run cmd/main -- shift examples/noted.vtt 1s
WEBVTT

NOTE 这一份是演示用的，重点是文件里那两处 NOTE 和一个 STYLE 块

STYLE
::cue { color: yellow }

00:00:02.000 --> 00:00:05.000
这一行在样式块之后

NOTE 下面换了一个说话人

00:00:06.000 --> 00:00:09.000
第二行，它前面夹了一条注释
```

`info` 那行"非字幕块"只在真有这类块时才出现。转成 SRT 时它们会被丢掉，SRT 里没有对应的语法。

`NOTE` 的作用范围一直延伸到下一个空行为止。一条 `NOTE` 后面紧跟着时间行、中间没留空行的话，
那条 cue 会被算进注释里。规范就是这么定义的，浏览器也这么读，写注释时记得后面空一行。

### WebVTT 的文件头

签名行后面可以跟若干元数据行，规范里管这一段叫文件头：

```
WEBVTT
Kind: captions
Language: zh
```

这些行不是给观众看的，丢了却会改变文件的意思：`Language` 没了播放器挑不了语言轨，
`Kind` 没了就分不出辅助字幕和普通字幕。整块按原文收进 `Subtitle::header`，渲染时写回原位。
`examples/headed.vtt` 平移一秒，头还是那两行：

```
$ moon run cmd/main -- shift examples/headed.vtt 1s
WEBVTT
Kind: captions
Language: zh

NOTE 这一份演示文件头：签名行后面跟的是元数据行

00:00:02.000 --> 00:00:05.000
第一行

00:00:06.000 --> 00:00:09.000
第二行
```

元数据行必须紧贴签名行，中间不能空行。隔一个空行的话，它们会被当成一个正文块，
里面没有时间行，整块在解析时判坏。

签名行自己也可以带一句说明文字（`WEBVTT - 中文字幕`），一样保留。只写一个光秃秃的
`WEBVTT` 行的头不单独记，那等于没有多余信息，跟"没有文件头"存成同一个值。
`info` 那行"文件头"只列元数据行，签名行后面那句说明文字不进统计。
转成 SRT 时文件头会丢掉，原因同 `extras`。

## 库的用法

用法示例在 [README.mbt.md](README.mbt.md)。那些代码块由 `moon test` 一起校验，
改了 API 忘了改文档，测试会直接失败。设计上的取舍见 [DESIGN.md](DESIGN.md)。

模块划分：

| 文件 | 内容 |
|---|---|
| `time.mbt` | 时间戳解析与格式化 |
| `duration.mbt` | 时间量解析（`1.5s` / `500ms`） |
| `srt.mbt` / `vtt.mbt` | 两种格式的解析与渲染 |
| `subtitle.mbt` | 数据模型与时间轴变换 |
| `text.mbt` | 两种格式共用的文本处理 |
| `markup.mbt` | 标记剥离与实体解码 |
| `cmd/main` | 命令行工具 |

## 已知限制

- 只读 UTF-8。别的编码（GBK 等）会被拒绝、退出码 1，需要先用 `iconv` 这类工具转码。
  这是有意的，理由见 [DESIGN.md](DESIGN.md#编码不对也报错)
- 块首行必须是序号行。空行是 SRT 的块分隔符，不能拿它当正文换行。
  被空行隔开的块会按块号报错，不会被并进上一条；同一句分两行请写在同一个块里
- WebVTT 的 cue 标识行只认一行。时间行前面多出别的行会按块号报错，不会静默丢掉
- 时间精度到毫秒，再小的单位会被截断。毫秒不接受小数写法（`1.5ms` 报错）
- 时间值上限约 596 小时。秒和分钟的写法因为要支持小数，中间量放在千分之一单位里，
  上限被压到约 35 分钟
- 平移量把字幕推出这个范围时会截到上限，一前一后被顶到同一条上限的 cue 会退化成零长度
- 排版设置在 SRT 与 WebVTT 之间互转时会丢掉，两套键名没有交集。同一种格式转一圈不受影响
- `NOTE` / `STYLE` / `REGION` 和 WebVTT 的文件头，在转成 SRT 时都会丢掉，SRT 里没有对应语法
- `--output` 的"输出不能覆盖输入"是字符串级比较：折叠掉 `.`、`..` 和重复斜杠之后再比，
  所以 `./x.vtt`、`dir//x.vtt`、`dir/../x.vtt` 都拦得住。但拿绝对路径去指一个用相对路径
  写出来的同一个文件时，两个串长得不一样，拦不住
- native 目标需要 C 编译器，本机没装，所以 `moon.mod` 里把 `preferred_target` 定为 wasm

## 设计取舍

推导过程在 [DESIGN.md](DESIGN.md)，这里只列结论：

- 时间统一用毫秒整数，避免浮点秒数在连续变换里累积误差
- 手写字符串切分，不引入正则表达式（核心库没有内置正则，`moonbitlang/regexp` 仍是 alpha）
- 数值越界一律拒绝，不回绕；编码不对一律报错，不做宽松解码
- 块形状对不上就报错，不猜
- 不解析排版设置，也不剥标记，两类信息都按原文保留
- 库本体零第三方依赖。`moonbitlang/x` 只出现在 `cmd/main` 里，因为核心库没有文件 IO
